Detailed Description

◆ EMBENET_TIMER_SetCompare()

void EMBENET_TIMER_SetCompare ( EMBENET_TimeUs compareValue)

Schedules a compare event at the given absolute timer value.

The implementation must call the compareCallback registered in EMBENET_TIMER_Init when the hardware counter reaches compareValue.

Because the underlying counter wraps at 2^32 µs, the implementation uses EMBENET_TIMER_GetMaxCompareDuration to disambiguate past from future:

  • If the signed distance from the current counter to compareValue exceeds EMBENET_TIMER_GetMaxCompareDuration, the event is considered to be in the past and the callback MUST be invoked immediately.
  • Otherwise the compare interrupt MUST be scheduled for the future.

On lower-performance systems the implementation may apply a guard time (e.g. 20 µs): any compareValue within [current_time − guard, current_time + guard] MAY be treated as if it were in the past.

Parameters
[in]compareValueabsolute timer value at which the callback should fire, in microseconds.

◆ EMBENET_TIMER_GetMaxCompareDuration()

EMBENET_TimeUs EMBENET_TIMER_GetMaxCompareDuration ( void )

Returns the maximum duration that the timer considers to be in the future.

Used by EMBENET_TIMER_SetCompare to resolve the past-vs-future ambiguity introduced by the 32-bit counter wrap. If the forward distance from the current counter value to a requested compare value exceeds this limit, the compare event is treated as already past. The returned value must not exceed the timer period (2^32 µs). In most implementations the appropriate value is (timer period) / 2.

Returns
Maximum schedulable compare duration in microseconds.
