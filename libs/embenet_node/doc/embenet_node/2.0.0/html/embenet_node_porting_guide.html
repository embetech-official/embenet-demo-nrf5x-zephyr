embeNET Node Porting Guide

A port connects the embeNET Node stack to the hardware it runs on. It implements the functions declared in the embenet_port/ headers. Nothing else in the stack is hardware dependent.

Port interfaces

Header Interface Purpose
embenet_port/radio.h Radio Interface radio transceiver state machine, frame TX/RX, radio properties
embenet_port/timer.h Timer Interface free-running microsecond counter with one compare event
embenet_port/multiprotocol.h Multiprotocol Interface sharing the transceiver with another protocol
embenet_port/api_version.h Port API Version Marker port API version marker (EMBENET_PORT_API_V2)
embenet_port/aes128.h AES-128 Interface AES-128 block cipher
embenet_port/critical_section.h Critical Section Interface masking the stack's interrupts
embenet_port/random.h Random Number Generator Interface random numbers
embenet_port/eui64.h 64-bit Extended Unique Identifier (EUI-64) Interface the device's unique EUI-64
embenet_port/allocator.h Memory Allocator Interface the stack's buffer pool
embenet_port/border_router_communication.h Border Router Communication Interface link to the border router (root nodes only)

Every function of every interface must be implemented. The multiprotocol interface is the exception: only a port that shares the transceiver implements it. Any other port leaves it out entirely.

General rules

  • Every port defines void EMBENET_PORT_API_V2(void) {}. The stack calls it from EMBENET_NODE_Init, so a port written for another major version of the port API fails to link instead of linking against mismatched signatures. Every incompatible change of the port API bumps the version in the marker's name.
  • The port headers use only primitive types: bool, fixed-width integers and plain function pointers. A port can implement them without the stack's headers, so it builds without fetching embeNET Node.
  • All times are uint32_t microseconds in the time base of EMBENET_TIMER_ReadCounter(), and they wrap around. All powers are int8_t dBm.
  • The stack passes only valid arguments, so the port does not need to check them. Channels are below EMBENET_RADIO_GetChannelCount(). Powers lie within [EMBENET_RADIO_GetMinTxPowerDbm(), EMBENET_RADIO_GetMaxTxPowerDbm()]. Frame lengths lie within [1, EMBENET_RADIO_MAX_PSDU_LENGTH].
  • The radio does not report run-time failures. The MAC watchdogs recover from a radio that does not do what it was told. The only reported failure is EMBENET_RADIO_Init() returning false, which makes EMBENET_NODE_Init fail. The port must always leave the radio in a state from which EMBENET_RADIO_Idle() recovers.
  • EMBENET_RADIO_TxNow() returns false only when the channel is busy (listen-before-talk).
  • Each radio property getter (EMBENET_RADIO_Get*()) returns a worst-case value that the port implementor measures. These getters must work in every radio state, including UNINITIALIZED.

Channel plan and network configuration

The port defines how channel numbers map to frequencies, and EMBENET_RADIO_GetChannelCount() reports how many channels exist. The application selects the network configuration with one of the EMBENET_NODE_GetConfig_*() getters and passes it to EMBENET_NODE_Init. The port does not provide a configuration. EMBENET_NODE_Init rejects a configuration if any of its channels is not below EMBENET_RADIO_GetChannelCount().

The configurations shipped with the stack expect these channel plans:

Configuration Channel plan Channels
863_870Mhz_* SUN FSK frames, 2-FSK 50 kb/s, channel n = 863.1 MHz + n * 100 kHz 69
2400_2480Mhz_BLE_PHY_* BLE PHY, BLE channel numbering 40

Sharing the radio with another protocol

The stack can share the transceiver with another protocol on the same device, for example Bluetooth LE. In that mode the stack does not own the transceiver for its whole lifetime. Instead, it requests each timeslot from the port ahead of time. It uses the transceiver only in the timeslots the port grants, and it releases each timeslot as soon as it is done.

The multiprotocol support is linked in only when it is needed, so a firmware that does not share the transceiver carries none of its code. A port that shares the transceiver implements the multiprotocol functions and calls EMBENET_MULTIPROTOCOL_OnGranted() and EMBENET_MULTIPROTOCOL_OnEndGuard() from its arbiter. Those references link the stack's multiprotocol support in. A port that supports sharing can still run without it, for example when its build configuration turns sharing off: its EMBENET_MULTIPROTOCOL_Init() then returns false, and the stack owns the transceiver as usual.

Because such a port calls the stack back, the stack must come after the port on the link line. In CMake, link the port target to embenet::node (not $<COMPILE_ONLY:embenet::node>). When the port's sources are compiled into the application directly, the order is already right.

A shared transceiver brings three requirements that a single-protocol port never meets:

  • EMBENET_RADIO_Init() and EMBENET_RADIO_Deinit() run in every granted timeslot. EMBENET_RADIO_Init() must therefore restore every radio setting that the other protocol may have changed.
  • The stack reads the radio properties while the transceiver is uninitialized.
  • The stack's grant and end-guard callbacks may run at a priority that the critical section does not mask. From there they call EMBENET_TIMER_ReadCounter() and the radio functions.

See Multiprotocol Interface for the full contract.

Changes in port API v2

Porting a v1 port to v2 requires these changes:

  • embenet_port/capabilities.h and EMBENET_CAPABILITIES_Init are gone. The application passes the network configuration to EMBENET_NODE_Init.
  • EMBENET_RADIO_Capabilities, EMBENET_RADIO_GetCapabilities and the radio status codes are gone. In their place:
    • the EMBENET_RADIO_Get*() property getters and EMBENET_RADIO_GetChannelCount();
    • bool EMBENET_RADIO_Init() and bool EMBENET_RADIO_TxNow();
    • void returns from EMBENET_RADIO_Idle(), EMBENET_RADIO_TxEnable(), EMBENET_RADIO_RxEnable() and EMBENET_RADIO_RxNow().
  • EMBENET_RADIO_GetReceivedFrame reports the RSSI and the CRC status through output parameters instead of EMBENET_RADIO_RxInfo.
  • EMBENET_RADIO_StartContinuousTx is gone.
  • The timer reports EMBENET_TIMER_GetMaxCompareDurationUs(). The timer typedefs are gone.
  • EMBENET_BRT_SendRaw, EMBENET_BRT_ReceiveRaw and EMBENET_BRT_IsBusy are gone. Lengths are uint32_t.
  • EMBENET_PORT_API_V2() is new: an empty function every port defines.
  • embenet_port/multiprotocol.h is new. Only a port that shares the transceiver implements it.
