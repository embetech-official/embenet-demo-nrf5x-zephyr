Porting embeNET UDP

What a port provides

A port is whatever supplies the definitions for the C functions declared in embenet/udp.h: EMBENET_UDP_RegisterSocket, EMBENET_UDP_UnregisterSocket, EMBENET_UDP_GetMaxDataSize, EMBENET_UDP_Send, EMBENET_UDP_GetVersionString, and EMBENET_UDP_IsOsDependent. This repository ships three of them (linux, windows, fake, under ports/), each built as its own CMake target aliased as embenet::udp_port_<name>, and additionally as embenet::udp_port when it is the one selected via the EMBENET_UDP_PORT CMake option. An application can link any compatible port directly without going through that selection at all.

The EMBENET_UDP_OS_DEPENDENT contract

Some ports need to be driven periodically from the application's main loop or a dedicated thread; others are entirely self-contained (already integrated into a larger stack, or driving a simulation directly). udp.h uses one macro to describe which kind a given port is:

#ifndef EMBENET_UDP_OS_DEPENDENT
#define EMBENET_UDP_OS_DEPENDENT 0
#endif

A port sets this macro publicly on its CMake target, so that both the port's own translation units and every consumer including udp.h agree on the same value:

target_compile_definitions(embenet_udp_port_linux PUBLIC EMBENET_UDP_OS_DEPENDENT=1)
  • EMBENET_UDP_OS_DEPENDENT == 1 — the port polls or holds onto OS resources (e.g. a real BSD/Winsock socket) and needs to be pumped. It must also implement EMBENET_UDP_Proc (call periodically; it dispatches at most one received datagram per call to the owning socket's rxDataHandler) and EMBENET_SetSourceAddress (configures the node's own unicast source address). Both functions are declared by udp.h only when this macro is 1 — code written against a port that sets it to 0 will not even see these declarations. The linux and windows ports in this repository set it to 1.
  • EMBENET_UDP_OS_DEPENDENT == 0 (the default when a port sets nothing) — the port needs no periodic pumping: either it is a self-driven simulation (the fake port), or it is embedded inside a larger stack that already pushes received data into the socket registry directly. Such a port must not define EMBENET_UDP_Proc / EMBENET_SetSourceAddress, since nothing declares or calls them.

Querying it at runtime

The macro only helps code that is compiled against a specific port. An application that is written to be port-agnostic (for example, code that is compiled once and linked against whichever port a downstream build chooses) cannot branch on a preprocessor macro it never sees. For that case, every port also implements EMBENET_UDP_IsOsDependent, a plain runtime function that mirrors the macro's value:

if (EMBENET_UDP_IsOsDependent()) {
// only reachable at all when this translation unit was itself built with
// EMBENET_UDP_OS_DEPENDENT=1, since that's what makes EMBENET_UDP_Proc visible
EMBENET_UDP_Proc();
}

bool EMBENET_UDP_IsOsDependent(void)
Report whether this port requires EMBENET_UDP_Proc.
EMBENET_UDP_Proc

Process UDP reception events.

EMBENET_UDP_IsOsDependent and EMBENET_UDP_GetVersionString are the only two functions declared unconditionally by udp.h; every port must implement both regardless of which side of the contract it is on.

Checklist for a new port

  1. Implement EMBENET_UDP_RegisterSocket, EMBENET_UDP_UnregisterSocket, EMBENET_UDP_GetMaxDataSize, EMBENET_UDP_Send.
  2. Decide whether the port needs periodic pumping; set EMBENET_UDP_OS_DEPENDENT to 1 or 0 accordingly via target_compile_definitions(... PUBLIC ...).
  3. If 1, additionally implement EMBENET_UDP_Proc and EMBENET_SetSourceAddress.
  4. Implement EMBENET_UDP_IsOsDependent to return a value consistent with step 2.
  5. Compile ports/udp_version.c into the port target so EMBENET_UDP_GetVersionString is available — every existing port shares this one file rather than reimplementing it.
  6. Alias the resulting target as embenet::udp_port_<name>, and as embenet::udp_port when EMBENET_UDP_PORT STREQUAL "<name>".
